# 开源项目怎样介绍

## 推荐定位

**First Principles Council · 第一性原理议事厅**

> 别急着把点子做出来，先找出它靠什么成立。

英文短句：**Five lenses. One testable next move.**

一句话介绍：一个帮助判断商业机会与赚钱路径的 Agent skill：拆出隐藏假设，重新看客户真正要完成的事，给出有依据的选择和下一步验证。

“议事厅”指几种方法共同检查一个决定。它不是五位名人的数字分身，也不是默认启动五个 Agent。名字负责吸引注意，首页要用具体经营问题和真实答卷解释用途。

## 名人路线怎样用

在方法来源区写：“参考 Feynman 的科学诚信、Christensen 的客户任务、Kim 与 Mauborgne 的价值创新、Fitzpatrick 的访谈和 Torres 的持续发现方法。”每项链接一手来源，再说明它会改变哪一个判断。

不用“让五位伟人替你赚钱”“费曼认为这个项目能成”等话术，不放模拟签名或名人对话截图。原作者的声望不证明这个 skill 有效。主视觉展示一条机会命题如何变成支持证据、反证和下一步实验，比分发名人头像更能说明产品。

三个可测试的传播角度：

1. **“你的点子可能没错，但你可能找错了付款的人。”** 配购买链案例，展示原问题、重新定义后的问题和可验证动作。
2. **“不再让 AI 给你二十个副业点子。”** 展示已有资源和限制下的一条优先路线、一个可信备选，以及何时该改判。
3. **“给 AI 加一套思考方法，真的比直接问更好吗？”** 链接无技能/有技能原始答卷与盲评。包含平局和失败，不仅挑最好看的一题。

这些是待测试文案，不是已证明更高转化的营销结论。

## 发布顺序

1. **仓库首屏**：一句明确用途，三步示例，离线下载入口，简短安装用法，最后放方法来源和评测边界。让访问者一分钟内知道它能交付什么。
2. **GitHub 个人主页**：放一个项目入口，描述为“拆解商业机会、识别隐藏假设、设计下一步验证”；保留其他产品内容，不用未验证的优越性宣称。
3. **首个 Release**：附无需 GitHub、Python 或 Node 依赖的离线包和中文说明。接收者可以通过微信拿到文件；使用 Agent 本身所需的账号和网络仍取决于其宿主产品。
4. **公开比较**：固定版本、同题材料、运行条件、全部答卷与判断依据。说明哪些题用于开发、哪些题在冻结后测试；真实收入与合成案例分开。
5. **社区分享**：由维护者在相关社区发布一篇完整案例，说明项目归属，邀请大家提交匿名化的反例。未经许可不上传客户材料，不群发推广。

早期最有用的反馈是：使用者能否复述“原来漏掉了哪个假设”，是否完成了建议中的小验证，以及什么事实使建议改变。Star、下载量和好评只能说明传播或兴趣，不能证明判断质量或赚钱效果。

## 名称能否用

本项目将“第一性原理”用于描述思考方向，并用 **First Principles Council** 作为项目名。2026-11-04 的有限网页检索未确认一个精确同名的直接产品，但这不是独占性或可注册证明。

已有近似项目 [evisoft/council](https://github.com/evisoft/council)，包含 `council-first-principles`。所以不能把“Council + First Principles”宣传为本项目首创。差异应该落在商业问题、证据链、离线便携与公开对照上。
